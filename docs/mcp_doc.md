# MCP 服务 🔧(Model Context Protocol) 服务使用说明文档

**文档更新时间：2026年6月23日**

**Anywhere Desktop** 对 **MCP (Model Context Protocol)** 提供了深度支持。借助 MCP，AI 不再只是聊天模型，而是能够在桌面端真实调用本地文件、执行命令、运行脚本、联网搜索、调度任务，甚至与其他 Agent 协作的工作执行体。

本文档将说明如何在桌面端配置和使用 MCP 服务，把 Anywhere Desktop 升级为真正的本地 AI 自动化工作站。

---

## 1. 前置准备 (必读)

在使用 MCP 之前，请先确认当前电脑满足以下环境要求。

### 1.1 环境安装

绝大多数外部 MCP 服务依赖 Python 或 Node.js 运行。

* **Python 环境**：如果要使用 Python 相关 MCP 或内置 Python 执行器，请先安装 Python 或 Anaconda。
* **Node.js 环境**：若要运行基于 `npx` / JavaScript 的 MCP 服务，请先安装 Node.js。
* **Git**：部分第三方 MCP 或技能流程会依赖 Git。

**⚠️ 重要提示：**
安装或修改环境变量后，建议完全退出并重新启动 Anywhere Desktop；必要时可重启电脑，以确保主进程能读取到最新 PATH。

### 1.2 模型要求

MCP 的核心依赖是 **Function Calling（工具调用）**。

* **推荐模型**：Claude、GPT-4o、DeepSeek-V3 / R1 等工具调用能力强的模型。
* **不推荐模型**：工具调用能力弱、格式不稳定、无法稳定输出 JSON 参数的模型。

## 2. 内置 MCP 服务 (开箱即用)

Anywhere Desktop 预置了一组桌面端高频使用的内置 MCP 服务。建议默认保持启用，它们构成了桌面自动化的基础能力。

* **🤖 Super-Agent**：
  * 用于多 Agent 协作；
  * 支持后台子智能体（Sub-Agent）；
  * 支持调度其他独立窗口中的 Agent；
  * `sub_agent` 支持 `model_route` 参数，可按 **强思维 / 通用 / 快速** 三类默认助手路由选择后台模型。
* **📂 File Operations**：
  * 读、写、精确替换、正则替换、插入、搜索文件内容；
  * 对代码 / Markdown / 文本文档处理尤其高效。
* **🐍 Python Executor**：
  * 自动扫描本机 Python 环境；
  * 允许 AI 生成并运行 Python 脚本。
* **💻 Shell Executor**：
  * 在 Windows 下默认执行 PowerShell；
  * 支持后台长任务与日志读取。
* **🌐 Web Toolkit**：
  * 提供联网搜索、网页抓取与远程内容读取能力；
  * 网页抓取支持通过 `markitdown-js` 将复杂网页转换为更易读的 Markdown。
* **🧩 Better Work**：
  * 提供对话内选择卡片 `ask_user_choice`，边界交互，让AI更加理解用户想法；
  * 提供会话临时任务清单 `task_write` / `task_read`，可在任务面板中实时展示进度（`Ctrl+T` 快捷展示/收起任务面板）。
* **⏰ Task Manager**：
  * 允许 AI 创建、更新和管理桌面端定时任务。
* **🕒 Time Service**：
  * 提供当前时间与时区时间读取能力。

### 2.1 内置文件与搜索工具增强

内置文件工具适合让 AI 精确修改代码、Markdown 或配置文件。当前版本对这些工具做了增强：

* **编辑后回显变更片段**：文件编辑成功后，会返回修改附近的行号片段，方便确认结果。
* **编辑失败诊断**：当精确匹配失败时，会提示可能的空白、行号或相近文本问题。
* **误带行号容错**：如果 AI 不小心把 `read_file` 展示用的 `NNNN | ` 行号带入匹配内容，工具会尝试自动纠正。
* **搜索输出限流**：`grep_search` 默认限制结果块、上下文行数、单行长度与总字符数，避免一次搜索返回过长内容挤占上下文。

### 2.2 Better Work 交互工具

Better Work 是一组面向“长任务协作”的内置 MCP 工具：

* **`ask_user_choice`**：让 AI 在对话气泡中展示选择卡片。每题单选，并自动提供自由输入与讨论选项，适合确认方案、选择分支或收集偏好。
* **`task_write`**：让 AI 写入当前会话的临时任务清单，任务面板会展示待办、进行中、已完成状态与子步骤。
* **`task_read`**：让 AI 在长对话或上下文压缩后重新读取当前任务面板，恢复进度，避免忘记已完成事项。

任务面板支持半透明显示、拖拽定位、状态标识，并可通过 `Ctrl + T` 快速显示或隐藏。

> 建议：当 AI 需要维护任务清单时，应先调用 `task_read` 获取最新状态，再调用 `task_write` 写入完整快照；每完成一个步骤后立即更新任务面板。


## 3. 添加自定义 MCP 服务

除了内置服务外，也可以接入社区中的第三方 MCP 服务。

### 3.1 配置类型 (Type)

#### Stdio (标准输入输出)

这是最常见的本地 MCP 形式，桌面端会以子进程方式启动它。

* **命令 (Command)**：如 `npx`、`python`、`uv`、`docker`。
* **参数 (Args)**：每行一个参数。
* **环境变量 (Env)**：用于填写 API Key 或其它运行所需环境变量。

![img](..\image\MCP配置界面.png)

#### SSE / HTTP

用于连接本地或远程运行中的 HTTP MCP 服务。

* **URL**：填写完整地址，例如 `http://localhost:3000/sse` 或 `http://127.0.0.1:3000/mcp`。

### 3.2 关键设置

* **持久连接 (Persistent Connection)**：
  * **关闭**：按需启动、用完即断，节省资源；
  * **开启**：服务常驻后台，适合启动很慢或需要保持状态的 MCP。

对于桌面端来说，持久连接适合数据库连接、长生命周期 REPL、索引服务等场景。

## 4. 在对话中使用 MCP

### 4.1 启用服务与工具

在独立对话窗口中，可以通过输入区下方的 MCP 面板，选择本次对话允许调用的服务与工具。

* 支持按服务粒度启停；
* 也支持关闭某个服务下的特定工具，减少误调用风险。

### 4.2 AI 如何调用

启用后，不必手动描述工具细节，只需自然表达目标即可。

例如：

* *用户*：“帮我在项目里找一下所有用到 `handleSubmit` 的地方。”
* *AI (后台)*：调用 `grep_search`。
* *AI (回复)*：给出命中文件与行号。

再例如：

* *用户*：“帮我开一个专门写文案的 Agent，把这段内容润色一下。”
* *AI (后台)*：可调用 `summon_agent` / `sub_agent` 等能力完成任务。

### 4.3 请求进行中的消息缓冲

当 AI 正在回复或 MCP 工具仍在执行时，仍可以继续输入下一条消息。新的消息不会打断当前请求，而是进入缓冲队列：

* 当前 AI 回复或工具调用完成后，缓冲消息会自动追加为新的用户消息；
* 多条缓冲消息会保持独立，便于保留真实对话顺序；
* 在正式发送前，可以从输入区上方的缓冲卡片中取消某条待发送内容。

这适合在长工具调用过程中继续补充资料、追加要求或准备下一步指令。


### 4.4 审批机制 (安全锁)

为了防止 AI 在桌面端执行危险操作，Anywhere Desktop 提供审批机制：

* **手动批准**：默认推荐。每次工具调用前由确认。
* **自动批准**：适合高度信任的自动化场景，但请谨慎开启。

涉及删除文件、覆盖内容、执行系统命令等操作时，建议保留人工确认。

## 5. 常见问题 (FAQ)

**Q1: 添加了 Stdio 服务，但连接测试失败怎么办？**

> **A:**
>
> 1. 检查命令是否存在于系统 PATH；
> 2. 若是 `npx`，检查 Node.js 与网络环境；
> 3. 若是 Python，必要时使用绝对路径，如 `C:\Python311\python.exe`；
> 4. 修改环境后建议重启桌面端。

**Q2: 为什么持久连接数量满了？**

> **A:** 持久连接会持续占用系统资源。若同时开启太多第三方服务，可能出现资源占满或连接上限问题。建议关闭长期不用的持久服务。

**Q3: 为什么 AI 总是乱调工具或参数格式错误？**

> **A:** 这通常与模型的工具调用能力有关。请尽量选用支持函数调用且稳定输出结构化参数的模型。

**Q4: 修改 MCP 环境变量后需要重启应用吗？**

> **A:** 一般建议刷新或重连对应服务；若 PATH 等系统环境变动较大，建议直接重启桌面端。

**Q5: Better Work 任务面板和定时任务有什么区别？**

> **A:** Better Work 任务面板是当前会话内的临时进度清单，用于让 AI 在一段长对话中展示执行状态；定时任务是桌面端后台调度能力，可按时间自动执行任务。前者偏“当前协作过程”，后者偏“长期自动化调度”。


**Q6: MCP 和 Skill 有什么区别？**

> **A:**
>
> * **MCP** 是工具，是 AI 的“手”；
> * **Skill** 是流程与规范，是 AI 的“SOP / 方法论”；
> * Skill 往往会指导 AI 正确调用 MCP 来完成具体工作。
